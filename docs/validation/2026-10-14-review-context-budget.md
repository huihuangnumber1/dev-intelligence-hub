# PR 评审输入大小不一致导致的阻塞

## 原因与修复

2026-10-14 本机排查发现：PR 预览允许 96 KiB，岗位上下文允许总计
128 KiB，但上下文规范化同时把单个字符串限制在 64 KiB。一个实际任务的
diff 为 67,274 字节，整个上下文为 81,468 字节，仍在总预算内，却在调用模型
之前抛出未分类的 `TypeError`。循环将其记录为 `ROLE_DECISION_FAILED`，
重试三次后进入 `decision_attempts_exhausted`。重复排队无法修复这一输入校验错误。

单个字符串现在复用已有的 128 KiB 上下文预算。序列化后的完整上下文仍受
128 KiB 总限制；控制字符、深度和结构检查保持有效。该预算约束传给模型的
上下文预览，原生只读工具仍负责读取绑定 Head 的完整变更；预览通过不代表
已经读完代码，更不代表已经发布 Review。

## 验证

- 新增 66,000 字节的 UTF-8 diff 回归，修复前复现相同错误，修复后进入模型调用。
- 超出总预算的输入仍返回 `ROLE_CONTEXT_TOO_LARGE`，非法控制字符仍被拒绝；
  两者均不得进入模型调用。
- 原生适配器集成回归验证大预览可以到达完整读取检查，读取不完整仍返回
  `PR_REVIEW_READ_INCOMPLETE`。
- 岗位决策、原生读取、上下文组装、PR 服务、路由、原生适配器和工作循环共
  251 项测试通过，0 失败、0 跳过。
- 使用实际任务输入和生产组装器离线复现：修复前在规范化阶段失败，修复后
  到达替代模型入口。此检查没有调用真实模型或写入 GitHub。
- 受管重启成功，实际加载修复提交 `a2004d8af8`，配置仍为版本 39，
  `pendingRestart=false`，私有配置文件 SHA-256 与修复前一致。
- 原阻塞任务经所有者接口恢复后，真实 `gpt-6.1-sol / high` 完成完整读取并
  发布 `CHANGES_REQUESTED`；GitHub 已核对分配回作者、移除评审者 Assignee，
  原工作项和交接收据均为完成。私有 PR 内容和具体收据保留在仓库外。

真实运行验证仅覆盖这一轮自动评审与交接，不能据此宣布整个开发、编译、UI
测试和复测流程均已验收。

## 运行恢复

受管重启后核对实际加载的源提交和配置版本。对这类已经耗尽重试的工作项，
使用带修订号和输入摘要校验的所有者重试接口恢复原任务，保留尝试次数和历史；
不要直接编辑账本或批量重置任务。真实 Review 发布和人员交接需另外核对
任务收据及 GitHub 结果，不能以 HTTP 健康检查替代。
