# PR 来源切换与旧代码任务结算验证

## 问题与修复范围

基线为 `9228a1fbea8eab2a690090af2f3784085c18f8b6`，修复分支为
`fix/pr-head-cutover-recovery`。

旧代码任务因模型输出无效而暂停后，PR 更新到新 Head。
创建任务的确认已经完成，但提案因授权变化被隔离为 `proposal_stale`；
来源切换只能识别未执行的撤销确认，导致旧任务无法结算、新版本不能领取。
只验证服务健康或安全拦截，不能发现这段接续过程缺失。

修复通过历史提案、分派记录、确认计划、授权和收据核对旧任务，
使用既有受控取消流程结算旧执行；只有绑定的任务成为可信终态后，才激活新来源。
取消中、结果不确定、被安全隔离或证据不匹配时继续保留拦截。
旧确认和任务记录保留，不修改私有状态文件来放行。

## 开发期发现的相邻缺口

- 确认曾被观察为 `executing` 或 `failed`，随后权威确认完成时，旧观察不能阻止重新读取其结算结果。
- 读取确认或代码任务期间台账可能变化，取消必须在读完任务之后检查当前版本并同步入队。
  台账锁只覆盖检查与入队，取消的 Promise 在锁外等待，避免队列反向等待造成死锁。
- 服务在取消中重启后仍需保留拦截；可信结算收据到达后，必须验证新 Head 实际可领取。

上述要求及生命周期矩阵已加入 `docs/TESTING.md`，对应回归包含在常规 `npm test` 中。
