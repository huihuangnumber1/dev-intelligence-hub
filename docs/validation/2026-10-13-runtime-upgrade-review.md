## 确认的问题与处理

| 问题 | 结果 |
| --- | --- |
| 已接受暂停/取消，同时模型到期且进程停止未确认时，控制错误被改写为普通超时，安排重试后原租约失效，控制无法结算 | 已修复：保留控制错误，等待可信停止证明，不安排普通重试；随后按原任务结算 |
| 原生超时测试依赖 35 ms 内完成文件准备；准备较慢时尚未注册中止监听，测试无限等待 | 已修复：等待执行入口，再推进模拟时钟，并设置测试等待上限 |
| 已结束任务的控制设置不回收，累计 1,000 个实体后新控制无法保存 | 尚未修复；需基于权威终态安全回收，见[待办与验收条件](../OPEN_FOLLOWUPS.md#p2--retire-terminal-task-control-settings-with-authoritative-evidence) |

暂停与取消的新增回归测试在修复前均观察到错误的 `retry_scheduled`，修复后保持
原修订号和租约，直至停止确认再结算。对超时测试注入 75 ms 准备延迟：原测试
超过等待上限，修复后通过。产品超时策略保持原义。
