# PR 重新排期与已有修复的内部复审

## 问题与边界

用户说明 #24723 的“我来修复”只指上一轮，并明确要求重新排期。正常
`POST /api/work/requests` 已将请求路由到 developer，但新工作项仍被
`pr_source_cross_root_cutover_pending` 阻断：旧根已经 cancelled，cutover
只把取消子任务视为终态，取消根会一直被列为 blocker。

修复允许晚于取消时刻的明确 owner PR 请求激活新来源，保留旧取消对象、
修订号和历史。普通自动观测、取消前的旧请求、不同 PR、未结算的执行或
副作用仍不满足激活条件；不通过改写私有状态或复活旧任务恢复。

研发修改前已有最新 Git target、代码差异及评审上下文读取。原决策提示
允许“无需修改”直接完成，现在要求先用代码与验证证据证明已有修复，
然后 `handoff / pr-review` 进入内部 PR 工程师队列，无需用户确认。
现有策略和分发器原子完成交接，不额外创建 confirmation、attention
或外部 proposal。内部复审不代表已经发送外部 GitHub 复审通知或获得批准。
