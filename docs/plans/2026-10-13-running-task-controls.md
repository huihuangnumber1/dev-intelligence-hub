# 当前运行任务与微调

## 目标

展示服务实际正在调用模型的任务，点击查看当前任务、岗位、开始时间和补充要求。支持补充要求、修改后续调度优先级、暂停、恢复、取消。沿用原任务和实体会话，不创建重复工作。

## 执行约定

源码核查见 [agent-feishu-bridge 接入分析](../research/2026-10-13-agent-feishu-bridge-source-review.md)。实时微调应通过可选的 Codex app-server 通道与 `turn/steer` 实现，严格绑定当前线程和回合。现有 `codex exec` 输入在启动时一次提交，检查点续接仅作为兼容行为：丢弃旧结果，使用新要求继续同一任务。界面必须区分提交回执、等待检查点、停止待确认与真正暂停。基础设施故障仍按现有故障规则处理。权限、固定测试、GitHub 发布校验及授权契约继续生效。

## 实施单元

- U1：新增 TaskRunRegistry，记录真实模型运行，持久化有界的补充要求、优先级和暂停状态，使用运行标识及修订号防止过期控制。独占 registry 模块及其测试。
- U2：新增当前运行视图模块，接入页面，详情展示生效状态和控制按钮。独占 public 文件及对应浏览器模块测试。
- U3：主代理接入岗位决策与代码任务、受信任 HTTP 端口和台账暂停恢复控制，追加模型用户消息，更新用户及运维说明。
- U4：独立实现可选 app-server 适配器及能力声明，用真实事件驱动运行详情，支持回合引导和经核实的中断；旧 exec 路线使用明确标注的兼容行为。完成协议与故障验证后再启用。

U1 与 U2 从本计划提交后的干净基线并行实施；U3 串行集成。代理不得提交、修改索引或运行全量测试。每个单元先检查既有测试，再用聚焦测试验证行为。

## 验证

覆盖：正在运行任务与排队任务区分；运行中追加要求使旧结果不可派发；暂停/取消后不执行旧决策；恢复沿用任务；过期运行及修订号拒绝；持久化失败不报告成功；重启保留暂停和补充要求；原权限不可扩张；前端无重复提交且明确待生效状态。最终运行相关服务、HTTP、前端测试，并审查集成差异。

配置及现有任务数据不迁移，不自动重启当前服务，不推送含其他本地提交的分支。
