# CLI 原生评审 skill 接入

## 目标

后台评审由 Codex CLI 显式调用原生 skill，按改动规模和风险分级；保留完整
Head 读取、结果校验、发布去重和人员交接。使用现有岗位模型和推理强度。

## 接入约定

- 原生入口为系统提供的 `dih-pr-review`，在每次调用目录的 `.agents/skills`
  注册；采用 `pr-review-tiering` 的后台适配流程，明确区别于原版 CE 全流程。
- 本机已安装的分级规则和 CE 审查视角作为技能资源读取，并记录内容摘要；
  不固定插件版本。缺少这些可选资源时明确记录实际覆盖，仍可使用内置评审流程。
- 技能及引用资料由受控只读 MCP 提供，避免依赖被策略拒绝的宿主文件命令。
- 中大型改动在 CLI 提供代理工具时使用有界的独立审查员；收齐结果后再合并。
  没有独立收据时必须说明覆盖限制，不得冒称 CE 或跨模型完整评审。
- CLI 只形成现有 WorkDecision，发布和分配由现有系统执行。技能不运行
  `gh pr review`，不执行仓库脚本或构建，不修改原仓库和用户配置。
- 非原生 CLI、非 Review 任务维持现有技能注入方式。

## 实现单元

### U1. 技能包与可信资源读取

增加原生入口和资源加载器；在 PR 只读端点提供技能文档，并校验入口完整读取。
验证资源缺失、路径及链接拒绝、摘要稳定和完整读取门禁。

### U2. 原生调用与岗位集成

只对原生 Review 在调用目录注册 skill，显式调用并按需启用代理工具；阻止环境
技能自动干扰。通过能力描述让岗位提示词不重复注入旧技能。清理只处理已知的
本次调用文件，保留未知残留和原生会话。

### U3. 验证、文档和运行检查

更新原生适配器及岗位集成回归；使用真实 CLI 和合成 PR 数据验证技能加载、
完整读取和结构化输出，不重复评审已交接的真实 PR。复核后本地提交、受管重启，
检查配置和真实运行状态。另行追踪 PR #24723 的自动修复状态。

### U4. 自身 PR 修复的检查续跑

修正 Git 镜像对合法含 `#` 分支名的误拒绝。仅对绑定当前 Head、已封存提案的
自动自身 PR 修复任务，在 inspect 成功后继续排入原任务并保留受信检查结果；
下一轮据此提出 modify/verify。失败、过期、手动检查及更新 Head 的结算规则保持。
保留 #24723 的失败记录，通过受管停止和独占写入租约重排原任务后验证。

### U5. 避免旧巡查覆盖自动修复

开启自动修复自身 PR 时，旧 PR 推进员工把 authored/address_review 留给现有
GitHub → 开发工程师通道；相关旧巡查作业保留为 superseded，重试不能重新派单。
真正手动派单、其他下一动作及关闭开关时的行为保持。对已误派给主控的 #24723，
用新鲜完整 GitHub 快照生成原生 observed 事件，经生产 routing.ingest/ledger.intake
恢复自动来源；不修改快照时间、不删除历史、不恢复旧执行 binding。

### U6. 自动开发的独立调度

仅在 GitHub 动作和自动修复自身 PR 均已开启时，让开发工程师采用现有独立岗位
调度，避免等待旧巡查及可选记忆投影。手动与定时触发按同一岗位合并，等待最新
事实刷新，保留维护准入、取消和停机排空。关闭或缺省开关时维持串行调度。
该单元只改善岗位领取和决策调度；提案执行、代码作业及推送仍走现有受控链路，
需分别观察实际执行收据，不以生成修改方案代替完成开发。

### U7. 派发租约使用已配置的时限

生产派发器遗漏了已验证的 `workCoordination.leaseDurationMs`，仍使用默认 30 秒，
导致有负载时修改提案已经持久化但回执超过租约。将已有配置传给派发器，保持
租约到期、幂等重放与权限校验；用组合根回归验证配置传递，不扩大用户权限。

### U8. 自动代码准备的处理预算

自动批准代码作业需要当前权限、GitHub 反馈、Git 对象准备及二次事实校验，
实测创建作业耗时约 75 秒；通用提案处理器默认 30 秒提前返回重试，底层随后仍
完成，产生误导状态。仅为已开启的自身 PR 自动修复使用与这些前置阶段相称的
有界处理预算，并限制在已配置租约内；普通代码提案保留既有默认。保持幂等、
Head 校验及失败重试，不将超时结果冒称为代码已修改。

### U9. 固定 Head 快照恢复超时

重启后 #24723 自动恢复在 Git 快照准备阶段报 `GIT_SNAPSHOT_TIMEOUT`，原会话历史
保留。定位具体 Git 命令及负载原因，再最小修复；保持对象身份、总大小、文件数、
路径与可信 Git 边界验证。恢复失败不能当作模型已执行或改动已交付。

### U10. 将执行失败和恢复请求送达下一轮决策

#24723 修复基础设施后重新领取，却因上下文只含“任务失败”再次交给主控。
新增只读失败作业上下文，核对当前执行 binding、作业及记忆收据，提供安全错误码、
已观察动作及历史是否完整。仅将同一作业失败后所有者记录的重新排队说明作为恢复
背景；不改写原结果，不把重试说明当作修复完成证据，不扩大原执行或发布权限。

### U11. 原生 CLI 忙碌时不重复排队检查可用性

U10 部署后的开发轮次三次在领取前报 ROLE_RESOLUTION_TIMEOUT。原生适配器首次
共享目录调用尚无 lastStatus 时，另一岗位的登录探测会排在模型调用后面。复现该
等待后，仅让 checkAvailability 在共享目录忙碌时跳过冗余探测；每次实际 generate
仍按 FIFO 校验目录、会话和 CLI。关闭、取消、未确认进程退出和不可用 app-server
仍拒绝准入，不改变登录内容或允许模型并发访问原生目录。

## 完成条件

- 原生技能真实加载、引用读取和输出有证据；相关回归通过。
- 原有发布、分配、取消、会话恢复及未知文件保留规则不被绕过。
- 记录实际分级及审查覆盖，不以技能加载成功代替评审完成。
- 文档、配置保留与部署检查完成。
